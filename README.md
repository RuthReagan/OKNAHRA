# OKNAHRA website rebuild — handoff notes

## What this is

A static (no server/database required) rebuild of the OKNAHRA site: plain
HTML/CSS/JS generated by `build.py` from the templates in `pages/`. Static
hosting means it can go live on **any** basic web host — including a simple
GoDaddy hosting plan on `oknahra.net` — with no ongoing app-hosting cost.

```
oknahra-site/
├── build.py              ← run this after any content edit: python3 build.py
├── pages/                ← per-page content (edit these, not dist/ directly)
├── css/, js/, images/    ← source assets, copied into dist/ on build
├── dist/                 ← THE DEPLOYABLE SITE — upload this folder's contents
│                            to your web host's document root (e.g. GoDaddy's
│                            File Manager / FTP, pointed at oknahra.net)
├── ASSET_MANIFEST.md     ← which real photo/logo file replaces which placeholder
└── README.md             ← this file
```

To rebuild after an edit: `cd oknahra-site && python3 build.py` — regenerates
everything in `dist/` from the templates.

## Membership purchases — Stripe Payment Links (no backend needed)

Per your call to start with Payment Links rather than a full member portal:

1. In the [Stripe Dashboard](https://dashboard.stripe.com/payment-links), create one **Product** per paid tier (Associate $100/yr, Native Non-Profit Associate $100/yr, Student $100/yr — confirm these are still current), each set to **recurring, yearly** if you want Stripe to handle renewal reminders/billing, or **one-time** if you'd rather members re-purchase manually each year.
2. Create a **Payment Link** for each Product.
3. In `pages/membership.py`, replace each `PASTE_STRIPE_PAYMENT_LINK_…` placeholder with its real Payment Link URL, then `python3 build.py`.
4. Do the same pattern for the Job Board's $100 listing fee and any paid events — the button markup already exists in `pages/job_board.py` / `pages/events.py`, just swap in a real link the same way.

This gets you real payment collection with **zero backend code** — Stripe hosts the checkout page and emails receipts. The tradeoff (as discussed): no login portal, no automatic member roster — you'll see payments in the Stripe Dashboard and can export a CSV for your own records.

## Phase 2 — full member portal (accounts, auto-renewal, admin dashboard)

You asked to prep for this even though we're launching with Payment Links.
What upgrading to a real portal (like the previous CBSC.io build) requires,
so it's a clean addition rather than a rebuild:

- **App hosting** — static file hosting (what this site needs) can't run
  server code. A portal needs a host that runs a backend (e.g. Vercel,
  Render, or similar) — this can run alongside the marketing pages, or the
  whole site can move onto that platform.
- **A database** — to store member records, payment history, and renewal
  status (e.g. Postgres via Supabase/Neon, or similar).
- **Stripe webhooks** — a small server endpoint that listens for Stripe's
  "payment succeeded" / "subscription renewed" events and updates the
  database automatically (this is the piece Payment Links alone can't do).
- **Authentication** — member login (email/password or magic-link).
- **Admin dashboard** — the reporting/export views the board would use.

Because this rebuild already separates membership tiers, pricing, and board
data into plain, structured Python (`build.py`, `pages/membership.py`), that
data maps cleanly onto future database tables — it doesn't need to be
re-modeled from scratch when you're ready for phase 2.
